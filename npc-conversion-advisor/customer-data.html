NPC Conversion Advisor: why the app declares customer name, email, phone and address

For the Shopify App Store review, reference 147856. NPCoding, November 2026.

Short answer

The app never reads, stores or sends a customer's name, email, phone or address. It declares these four fields only because Shopify requires them for the one API the app is built on: the Admin GraphQL query shopifyqlQuery (scope read_reports). Shopify's documentation for that query states the requirement:

"Level 2 access to Customer data including name, address, phone, and email fields."

Source: shopify.dev/docs/api/admin-graphql/latest/queries/shopifyqlQuery. If the fields are removed, shopifyqlQuery is no longer available to the app and its main function (the store's conversion funnel and the fixes derived from it) stops working.

What the app reads

Access scopes: read_reports, read_products, read_shipping, read_orders. No read_customers. Every ShopifyQL statement the app sends is a store-wide total or a total per day, week, device, channel, landing page or product:

FROM sessions SHOW sessions, sessions_with_cart_additions, sessions_that_reached_checkout, sessions_that_completed_checkout SINCE … UNTIL …
FROM sessions SHOW sessions, sessions_that_completed_checkout GROUP BY session_device_type SINCE … UNTIL … ORDER BY sessions DESC LIMIT 20
FROM sessions SHOW sessions, sessions_that_completed_checkout GROUP BY referring_channel SINCE … UNTIL … ORDER BY sessions DESC LIMIT 100
FROM sales SHOW orders, total_sales SINCE … UNTIL …
FROM sessions SHOW sessions, sessions_with_cart_additions, sessions_that_reached_checkout, sessions_that_completed_checkout GROUP BY week SINCE -182d UNTIL today ORDER BY week
FROM sales SHOW orders, total_sales GROUP BY week SINCE -182d UNTIL today ORDER BY week
FROM sessions SHOW sessions, sessions_with_cart_additions, sessions_that_completed_checkout GROUP BY landing_page_path SINCE -30d UNTIL today ORDER BY sessions DESC LIMIT 250
FROM sales SHOW net_items_sold, total_sales GROUP BY product_title SINCE -30d UNTIL today ORDER BY total_sales DESC LIMIT 8

None of them selects or groups by a customer, billing or shipping column.

With read_orders the app reads only the number of orders and each order's total, so that test orders, which the ShopifyQL sales dataset leaves out, are counted too:

ordersCount(query: "created_at:>=… created_at:<…") { count precision }
orders(first: 250, query: "created_at:>=… created_at:<…") { nodes { currentTotalPriceSet { shopMoney { amount } } } }

No customer, email, phone, billing address, shipping address or line item is selected on an order. The app never queries the Customer or AbandonedCheckout objects.

Where the data is used

QueryShown to the merchant as
Sessions totalsThe store's funnel: visits, added to cart, reached checkout, completed checkout.
Sessions by deviceConversion per device type (mobile, desktop, tablet).
Sessions by referring channelConversion per traffic source.
Sales totals, order count and order totalsOrders and revenue of the period, used to estimate what each recommended fix is worth.
Sessions and sales by weekThe trend over the last 26 weeks in the daily report.
Sessions by landing pagePages that get visits but few add-to-carts.
Sales by product titleThe store's best sellers in the last 30 days.

What the app stores

For each store: the Shopify session (offline access token), the recommendations already shown with the merchant's answer (done / not for me), and the daily report settings: the store owner's email, the addresses the merchant chose to receive the report, unsubscribed addresses and a send log (day, number of recipients, delivery status). No record about the store's customers, so the customers/data_request and customers/redact webhooks have nothing to return or erase. shop/redact erases the recommendation history, the session, the report settings and the send log; an unsubscribed address is cut down to a one-way hash, so a reinstall never mails it again.
